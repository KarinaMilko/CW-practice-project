## 🎓 **Practice-Project: Демонстрація Навичок та Технічних Досягнень**

Цей репозиторій є **практичним портфоліо**, яке слугує демонстрацією всіх ключових навичок та знань, здобутих протягом курсу. Код відображає успішне впровадження наскрізних рішень у повноцінний проєкт, включаючи налаштування **складної інфраструктури**, реалізацію **фінансових транзакцій (CRUD)** та **стандартизацію API** відповідно до професійних вимог.

---

### ⚙️ Основні Технології

| Компонент | Технології | Призначення |
| :--- | :--- | :--- |
| **Бекенд** | Node.js, Express.js, Socket.IO | API та логіка сервера |

### 1. 🛠️ Локальна Конфігурація та Інфраструктура

Проєкт налаштовано для запуску на локальному середовищі (без Docker) з використанням локальних інстансів баз даних.

| Компонент | Налаштування | Зміна |
| :--- | :--- | :--- |
| **Серверний Порт** | `PORT` | 5000 (раніше 3000) |
| **PostgreSQL Host** | `host` | `localhost` (раніше `db-dev`) |
| **MongoDB Host** | `host` | `localhost` (раніше `mongo-dev`) |
| **Клієнтський Порт** | `serverPort` | 5000 (раніше 3000) |

#### Інструкції для Локального Запуску

Для підготовки локальної бази даних PostgreSQL необхідно виконати міграції та сідери:

```bash
# 1. Створити базу даних (якщо потрібно)
npx sequelize db:create
# 2. Запустити всі міграції (створить таблиці, включаючи Transactions)
npx sequelize db:migrate
# 3. Запустити всі сіди (включно з тестовими користувачами)
npx sequelize db:seed:all
```

### 2. 🏗️ Рефакторинг та Стандартизація

#### 2.1. 🔗 Рефакторинг Асоціацій Моделей (Sequelize)

Асоціації моделей були децентралізовані та перенесені безпосередньо у файли моделей (`server/src/models/*`).

| Модель | Встановлені Асоціації |
| :--- | :--- |
| **Contest.js** | `belongsTo(Users)`, `hasMany(Offers)` |
| **Offer.js** | `belongsTo(Users)`, `belongsTo(Contests)`, `hasOne(Ratings)` |
| **Rating.js** | `belongsTo(Users)`, `belongsTo(Offers)` |
| **User.js** | `hasMany(Offers)`, `hasMany(Contests)`, `hasMany(Ratings)`, `hasMany(Transactions)` |

#### 2.2. 🛣️ Рефакторинг API Роутів (RESTful стандартизація)

Виконано перехід від нестандартних `POST`-маршрутів та заголовків (`headers`) до ідіоматичних RESTful `GET`/`POST` маршрутів з використанням URL-параметрів (`params`) та рядків запиту (`query`).

| Функціонал | БУЛО | СТАЛО |
| :--- | :--- | :--- |
| **Створення Конкурсу (Оплата)** | `POST /pay` | `POST /contests` |
| **Всі Конкурси Креатора** | `POST /getAllContests` (параметри в body) | `GET /contests/?query` (параметри в query) |
| **Конкурси Замовника** | `POST /getCustomersContests` (статус у headers) | `GET /contests/byCustomer?query` (параметри в query) |
| **Отримання Конкурсу за ID** | `GET /getContestById` (ID в headers) | `GET /contests/:id` (ID в params) |

#### 2.3. 🛡️ Уніфікація Аутентифікації

Middleware `checkToken.checkToken` було видалено з кожного окремого захищеного маршруту та застосовано як загальний префікс (`router.use(checkToken.checkToken)`) для більшості маршрутів у `server/src/router/index.js`, значно спрощуючи конфігурацію роутера.

### 3. 💳 Реалізація Системи Транзакцій

Впроваджено повноцінну систему обліку фінансових операцій користувачів, пов'язану з моделлю `Users` через асоціації.

#### 3.1. Структура та Моделі

* **Таблиця Transactions**: Додано нову міграцію та модель з полями `amount`, `operationType` (`INCOME` / `EXPENSE`) та зовнішнім ключем `userId`.
* **Асоціація**: Встановлено двосторонній зв'язок: `User` має багато `Transactions`.

#### 3.2. Логіка Обліку

Логіка запису транзакцій інтегрована в контролер `userController.js`:

* **Оплата конкурсу** (`POST /contests`): Створюється транзакція типу `EXPENSE`.
* **Виведення коштів** (`POST /cashout`): Створюється транзакція типу `INCOME`.

#### 3.3. API та Клієнтський Інтерфейс

* **Приватний API Ендпоінт**:
    `GET /users/id/transactions?limit=...&offset=...` - для отримання історії транзакцій авторизованого користувача.
* **Публічний API Ендпоінт**:
    `GET /offers` - Додано загальнодоступний маршрут для відображення пропозицій, що виграли (`OFFER_STATUS_WON`), з підтримкою пагінації.
* **Клієнт**: Додано сторінку `/transactions` на фронтенді, інтегровану з Redux для відображення фінансової історії.
